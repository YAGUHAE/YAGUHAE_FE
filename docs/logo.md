## 로고는 두 개입니다

| 자산 | 쓰는 곳 |
|---|---|
| **워드마크** `야구해` | 헤더 · 스플래시 · 문서 표지 — 서비스명이 글자로 드러나야 하는 곳 |
| **마크** 「Y」 | 앱 아이콘 · 파비콘 · SNS 프로필 — 정사각/원형 안에 갇히는 곳 |

둘은 **같은 조형 언어**를 씁니다 — 오블리크 10°, 획 22/100, 완전히 둥근 캡. 그래서 나란히 놓아도 한 벌로 읽힙니다(`Logo/Lockup-Horizontal`).

## 0. 레퍼런스에서 가져온 것 / 버린 것

plab 로고는 심볼이 없는 **소문자 워드마크 단독**입니다. 뜯어보면 성격을 만드는 장치가 4개입니다.

| 장치 | plab | 야구해 반영 |
|---|---|---|
| 오블리크 | 약 10° 기울기, 이탤릭체가 아니라 정체를 전단(shear)한 것 | **가져옴** — 10° |
| 슬릿 카운터 | `p`·`a`·`b`의 속공간이 좁고 양끝이 완전히 둥근 사각 | **가져옴** — `ㅇ`·`ㅎ`의 카운터를 라운드 슬릿으로 |
| 지오메트릭 헤비 | 굵은 모노라인, 코너만 살짝 라운드 | **가져옴** — 스트로크 21/100, 코너 반경 6 |
| 웜 오프화이트 | `#F0EDE6` 계열을 어두운 면 위에 | **버림** — 우리 팔레트에 웜 화이트가 없고, 새 primitive를 추가할 만한 이유가 아닙니다. `gray/0`(순백) 사용 |

**폰트를 기울여 쓰지 않았습니다.** Noto Sans KR에는 이탤릭이 없고, Figma Plugin API의 `relativeTransform`은 회전·이동만 지원해 전단을 걸 수 없습니다(§6-1). 그래서 한글 모듈(가로·세로 획, 링)을 **좌표로 직접 그린 단일 벡터**입니다. 결과적으로 로고에 폰트 의존성이 없고, 어느 환경에서도 형태가 동일합니다.

## 1. 3개 안 (A 확정)

검토했던 3개 안입니다. **A로 확정**했고, B·C는 지우지 않고 `🏷 Logo` 페이지 하단 `90 · 미채택` / `91 · 미채택` 프레임에 투명도를 낮춰 남겨 뒀습니다. 마스터 벡터도 `M/Wordmark-Upright (미채택)` · `M/Symbol-HomePlate (미채택)`로 이름만 바꿔 보존했습니다 — 나중에 세컨더리 그래픽이 필요해질 때 다시 꺼낼 수 있습니다.

| 안 | 구성 | 강점 | 약점 |
|---|---|---|---|
| **A · 오블리크 워드마크** ✅확정 | 10° 오블리크 워드마크 단독 + 앱 아이콘은 첫 음절 「야」 모노그램 | plab 계보를 가장 정직하게 따름. 워드마크와 아이콘이 **같은 형태 언어**를 쓰므로 별도 심볼을 관리할 필요가 없음. 16px까지 「야」가 살아남음 | 로고 단독으로는 "야구"라는 종목이 형태로 드러나지 않음 (글자로만 전달) — **이 약점 때문에 마크를 「Y」+야구공으로 교체했습니다(§2-2)** |
| **B · 홈플레이트 심볼** | 정체(0°) 워드마크 + 위에서 본 홈플레이트 오각형 | 오각형은 야구에만 쓰이는 형태라 설명이 필요 없음. 원형 크롭·파비콘에서 형태가 죽지 않음 | 심볼과 워드마크가 별개 자산이라 둘의 균형을 계속 관리해야 함. 작은 크기에서 위치핀·하트로 오독될 여지 |
| **C · 빈 자리** | 오블리크 워드마크 + 로스터 스트립(6칸 중 1칸 빈) 언더바 | P-1 히어로의 "한 칸 비어 있는 로스터 스트립"과 직결. 서비스가 왜 존재하는지를 형태가 말함 | 스트립은 야구 고유 기호가 아니어서 **로고 단독으로 "야구"가 읽히지 않음**. 아이콘만 떼면 이퀄라이저·메뉴 아이콘으로 보임 |

### A안을 추천하는 이유

1. **관리할 자산이 하나입니다.** 심볼을 따로 만들면 워드마크와 심볼의 광학 무게, 정렬, 축소 대응을 각각 관리해야 합니다. A안은 워드마크를 잘라 아이콘을 만들므로 워드마크만 정확하면 아이콘도 정확합니다.
2. **레퍼런스와 같은 결정입니다.** plab이 심볼 없이 버티는 이유도 같습니다.
3. **P-1 히어로와 충돌하지 않습니다.** 화면설계서는 P-1 히어로를 의도적으로 로고가 아니라 로스터 스트립으로 두었습니다(`design-system.md` §6). C안은 그 자리를 로고가 선점해 히어로의 논지를 흐립니다.

**C안의 개념은 버리지 않아도 됩니다.** A안으로 확정하더라도 스트립은 지금처럼 P-1 히어로 그래픽으로 남으므로, 브랜드 전체에서는 두 요소가 역할을 나눠 갖습니다.

## 2. 조형 규칙 (재현에 필요한 전부)

로고는 스크립트로 생성된 벡터입니다. **아래 수치가 원본 사양이며, Figma 벡터는 그 산출물입니다.** 다시 만들거나 수정할 때는 Figma에서 점을 옮기지 말고 이 표를 고쳐 재생성하세요.

### 전역 파라미터

| 항목 | 값 |
|---|---|
| 음절 높이 (유닛) | 100 — 베이스라인 `y = 100`, 캡 `y = 0` |
| 기본 스트로크 `S` | 21 |
| `ㅎ` 전용 스트로크 `S2` | **16** — `ㅎ`은 꼭지+가로+원을 100 안에 쌓아야 해서 21로는 물리적으로 안 들어갑니다 |
| 코너 반경 | `S` 요소 6 / `S2` 요소 5 |
| 오블리크 | 10° → `K = tan(10°) = 0.17633`, 전단축은 **베이스라인**: `x' = x + K · (100 − y)` |
| 카운터 | 외곽 타원(시계) + 내부 라운드 사각(반시계), 반경 = 짧은 변 ÷ 2, `windingRule: NONZERO` |
| 음절 폭 | 야 116 · 구 100 · 해 120 |
| 트래킹 | 야→구 **16** / 구→해 **22** (비대칭입니다 — §2-1) |
| 전체 폭 | 374 유닛 (오블리크 오버행 포함 실 바운딩 384) |

### 글리프 좌표

`rr(x, y, w, h)` = 라운드 사각, `ring(cx, cy, rx, ry, sw)` = 슬릿 카운터 링.

```
야  ring(31, 50, 31, 51, 21)      ㅇ
    rr(72,   0, 21, 100)          ㅑ 기둥
    rr(85,  18, 31,  21)          ㅑ 위 획
    rr(85,  53, 31,  21)          ㅑ 아래 획
구  rr( 0,   0, 96,  21)          ㄱ 가로
    rr(75,   0, 21,  46)          ㄱ 세로
    rr( 0,  58, 100, 21)          ㅜ 가로
    rr(39.5, 58, 21,  42)         ㅜ 기둥
해  rr( 8,   0, 32,  16)          ㅎ 꼭지
    rr( 0,  24, 48,  16)          ㅎ 가로
    ring(24, 74, 24, 26, 16)      ㅎ 원
    rr(58,   0, 21, 100)          ㅐ 기둥 1
    rr(71, 39.5, 36, 21)          ㅐ 가로
    rr(99,   0, 21, 100)          ㅐ 기둥 2
```

**획은 겹쳐서 잇습니다.** `ㅑ`의 획이 `x = 85`에서 시작해 기둥(72~93) 안으로 8유닛 파고드는 것, `ㅐ`의 가로가 기둥 2(99~120) 안까지 들어가는 것은 의도입니다. 딱 맞춰 붙이면 이음매에서 코너 반경 때문에 잘록한 홈이 생깁니다.

### 2-1. 트래킹이 비대칭인 이유

`구`의 `ㅜ` 가로획과 `해`의 `ㅎ` 가로획이 **둘 다 글자 중간 높이에 꽉 찬 수평선**입니다. 같은 간격을 주면 이 구간만 시각적으로 붙어 보입니다. 그래서 구→해만 6유닛 더 벌렸습니다. `야`의 오른쪽은 `ㅑ` 획 두 개라 위아래가 비어 있어 같은 문제가 없습니다.

### 2-2. 「Y」 마크 (2026-08-13)

「야」 모노그램을 대체했습니다. **한글 마크는 서비스가 뭘 하는 곳인지 형태로 말하지 못했고**, 아이콘 한 칸 안에서는 그게 유일한 정보였습니다. 야구공을 넣으면 종목이 즉시 읽힙니다.

Y는 캡슐(양끝이 완전히 둥근 획) 3개로 그립니다. 워드마크와 같은 100유닛 격자·10° 오블리크를 씁니다.

| 항목 | 값 |
|---|---|
| 획 두께 | 22 (워드마크 21과 1 차이 — 대각선은 같은 두께로 그리면 얇아 보입니다) |
| 캡 | 완전 라운드 (반경 = 획/2 = 11) |
| 왼팔 | 중심선 `(14,13) → (46,53)` |
| 오른팔 | 중심선 `(78,13) → (46,53)` |
| 기둥 | 중심선 `(46,49) → (46,90)` — 팔보다 길어야 Y로 읽힙니다 |

**캡슐 = 폭의 절반을 반경으로 둔 라운드 사각형을 회전시킨 것**입니다. 베지어는 아핀 변환에서 제어점만 옮기면 정확히 변환되므로, 회전 → 전단을 연달아 걸어도 형태가 근사되지 않습니다.

#### 야구공

| 항목 | 값 |
|---|---|
| 공 지름 | 타일의 **84%** |
| 실밥 | 두 개의 3차 베지어, 열린 패스 + `strokeCap: ROUND`, 두께 공 지름의 7% |
| 실밥 좌표 | `(27,10) → C(12,32) (12,68) → (27,90)` 과 좌우 대칭 (공 100 기준) |
| Y 높이 | 타일의 **58%** |
| 색 | 셋 다 `color/text/on-brand-strong`(흰색) 하나에 묶고 **불투명도로만** 나눔 — 공 10% · 실밥 26% · Y 100% |

**색을 하나로 묶은 이유:** 공·실밥·Y가 같은 토큰을 쓰므로 타일 색을 바꿔도 톤 관계가 그대로 유지됩니다. 토큰을 3개 쓰면 다크모드나 리브랜딩에서 셋의 대비가 따로 놀게 됩니다.

**실밥이 가장자리로 휩니다.** 실제 야구공 실밥은 가운데로 휘지만, 그렇게 그리면 Y의 팔과 겹쳐 **X처럼 읽힙니다**(실제로 첫 시안이 그랬습니다). 가운데를 비우면 Y가 먼저 읽히는 대신 실밥이 다소 괄호처럼 보입니다 — 마크의 첫 번째 임무가 "Y로 읽히는 것"이므로 이쪽을 택했습니다.

## 3. 사용 규격

| 항목 | 규정 |
|---|---|
| 여백 | 사방 최소 **X = 워드마크 높이의 1/2** |
| 최소 크기 | 워드마크 **높이 20px** / 마크 **20px**. 그 아래에서는 워드마크를 쓰지 않고 마크만 씁니다 |
| 아이콘 코너 반경 | 아이콘 크기의 **22.5%** (1024 기준 230) |
| 아이콘 안 Y 비율 | 타일 크기의 **58%** (높이 기준), 광학 중앙 정렬 |
| 아이콘 안 공 비율 | 타일 크기의 **84%** |
| 컬러 | `green/500 #17854F` · `green/800 #093E26` · `gray/0 #FFFFFF` · `gray/900 #151915` **4개만** (공·실밥은 흰색의 불투명도 변형이라 새 색이 아닙니다) |

**20px가 최소 크기인 근거:** 그 아래로 가면 워드마크는 `해`의 `ㅎ` 꼭지(16유닛)와 `ㅇ` 슬릿이 1px 미만이 되어 붙고, 마크는 실밥(공 지름의 7% × 26% 불투명도)이 사라져 Y 단독이 됩니다. 데이터상 형태는 남아 있지만 렌더에서 뭉갭니다.

**마크는 20px 아래에서도 형태가 무너지지 않습니다.** 실밥만 없어지고 Y와 공은 남습니다 — 그래서 파비콘 16px을 허용해도 브랜드가 깨지지 않습니다. 다만 규격상 권장 하한은 20px입니다.

### 화면 안에서 어느 것을 쓰나

| 자리 | 쓰는 것 | 목업 |
|---|---|---|
| 로그인 · 스플래시 | **마크 위 + 워드마크 아래** 세로 락업 | P-1 · A-1 · 스플래시 미리보기 |
| 앱 헤더 (56dp) | **워드마크만** (높이 22~24) | P-3 · A-3 |
| 어두운 면 배너 | 마크 + 워드마크 가로 락업 | 배너 미리보기 |
| 파비콘 · SNS 프로필 | **마크만** | 브라우저 탭 · 원형 크롭 |

**헤더에는 마크를 넣지 않습니다.** 56dp 안에서 마크(24) + 워드마크(22)를 나란히 두면 좌측 40%를 브랜딩이 먹습니다. plab도 헤더는 워드마크 단독입니다.

**어두운 면 위의 마크는 타일을 뺍니다.** 딥 그린 배경이 이미 타일 역할을 하므로, 타일째 얹으면 사각형 경계가 이중으로 보입니다. 대신 공 불투명도를 10%→12%, 실밥을 26%→30%로 살짝 올려 배경과 분리합니다 (P-1 히어로가 이 방식입니다).

### 금지

- 가로/세로 비율 변경 (한쪽만 늘리기)
- 오블리크 각도 추가·변경, 회전
- 그림자·외곽선·글로우 추가
- 지정 4색 외의 색 사용 (`clay`·`amber`·`blue` 등 나머지 토큰 포함)
- `green/500` 면 위에 `green/800` 로고 (대비 부족)

## 4. Figma 컴포넌트 4종

`🏷 Logo` 페이지 → `05 · 컴포넌트`. fill은 전부 변수 바인딩이라 라이트/다크에서 자동 대응합니다.

| 컴포넌트 | fill 바인딩 | 용도 |
|---|---|---|
| `Logo/Wordmark` | `color/bg/brand` | 밝은 면 위 기본 워드마크 |
| `Logo/Wordmark-Reversed` | `color/text/on-brand-strong` (타일 `color/bg/brand-strong`) | 어두운 면 위 |
| `Logo/AppIcon` | 타일 `color/bg/brand-strong` + 공·실밥·Y 모두 `color/text/on-brand-strong` | 앱 아이콘 · 파비콘 · SNS 프로필 |
| `Logo/Lockup-Horizontal` | 위 둘의 조합 | 마크 + 워드마크 가로 락업 |

**공과 실밥의 반투명은 페인트가 아니라 노드 불투명도입니다.** `setBoundVariableForPaint`가 돌려준 페인트를 spread해서 `opacity`를 얹으면 **적용되지 않습니다**(§6-8). `node.opacity`를 쓰세요 — 변수 바인딩도 그대로 유지됩니다.

**`color/text/brand`가 아니라 `color/bg/brand`에 바인딩한 이유:** `text/brand`는 본문 대비를 맞추려 라이트 모드에서 `green/600`으로 한 단 어둡습니다. 로고는 본문이 아니라 브랜드 색 그 자체여야 하므로 `bg/brand`(= `green/500`, 흰 배경 대비 4.66:1로 AA 통과)를 씁니다. 다크 모드에서는 `green/400`으로 밝아져 어두운 배경에서도 읽힙니다.

**컴포넌트 페이지를 따로 만들지 않은 이유:** 파일 관례는 컴포넌트 1종 = 페이지 1개지만, 로고는 UI 컴포넌트가 아니라 브랜드 자산이고 규격 문서와 붙어 있어야 의미가 있습니다. `🏷 Logo` 페이지 안에 뒀습니다.

## 6. 작업 중 걸린 함정

1. **`relativeTransform`으로 전단(shear)을 걸 수 없습니다.** Figma Plugin API는 회전·이동만 지원합니다. 오블리크는 **경로 데이터에 좌표로 구워 넣어야** 합니다. 다행히 베지어는 아핀 변환 하에서 제어점만 옮기면 정확히 변환되므로, 라운드 코너와 타원도 전단 후 형태가 깨지지 않습니다 (근사가 아니라 정확합니다).
2. **`counterAxisAlignItems`에 `'STRETCH'`가 없습니다.** `'MIN' | 'MAX' | 'CENTER' | 'BASELINE'`뿐입니다. 자식을 늘리려는 것이었다면 자식 쪽 `layoutAlign`/`layoutSizing*`을 씁니다.
3. **획을 딱 맞춰 붙이면 이음매에 홈이 생깁니다.** 코너 반경 때문입니다. 반경만큼 겹쳐 놓고 `NONZERO`로 합집합 처리하세요.
4. **`ㅎ`은 기본 스트로크로 그릴 수 없습니다.** 꼭지+가로+원(카운터 포함)을 100유닛에 쌓으려면 스트로크가 21 이하로 내려가야 합니다. 획 굵기를 음절마다 균일하게 두려는 원칙보다 **밀도를 맞추는 것**이 우선입니다 — 한글 활자에서 `ㅎ`·`ㅆ` 같은 복합 자모를 얇게 쓰는 것과 같은 이유입니다.
5. **`exportAsync({ format: 'SVG_STRING' })`는 깨끗하게 나옵니다.** 단일 벡터를 넘기면 `<path>` 하나로 떨어지고, 슬릿 카운터의 반대 방향 와인딩도 SVG 기본 `fill-rule: nonzero`와 그대로 맞습니다 — 별도 후처리가 필요 없습니다.
6. **PNG는 Figma에서 직접 빼지 말고 SVG를 렌더하세요.** `exportAsync({ format: 'PNG' })`가 준 `Uint8Array`를 플러그인 샌드박스에서 손으로 base64 인코딩해 파일로 내렸더니 **바이트 수는 정확히 맞는데 내용이 깨졌습니다**(`file`은 IHDR만 읽어 180×180 PNG라고 정상 보고하므로 이걸로는 못 잡습니다 — 실제로 렌더해 봐야 압니다). 검증된 SVG를 헤드리스 크롬으로 렌더하는 쪽이 확실합니다:
   ```bash
   chrome --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
     --screenshot=out.png --window-size=180,180 page.html   # page.html이 SVG를 180×180으로 표시
   ```
7. **오블리크는 바운딩 박스를 좌우 비대칭으로 만듭니다.** 상단이 오른쪽으로 17.6유닛 밀리므로, 워드마크 왼쪽에 7.5유닛 정도의 빈 공간이 생깁니다(`ㅇ`의 최좌점이 중간 높이에 있기 때문). 여백 규정을 눈으로 맞추려 하지 말고 바운딩 박스 기준으로 잡으세요.
8. **`setBoundVariableForPaint`가 돌려준 페인트에 `opacity`를 얹어도 적용되지 않습니다.** `Object.assign({}, paint, {opacity: 0.1})`로 반투명 공을 만들었더니 **불투명 흰 원이 그려져 Y와 실밥을 전부 덮었습니다.** 노드 불투명도(`node.opacity`)를 쓰세요 — 변수 바인딩은 그대로 유지됩니다.
9. **`createVector`는 바운딩 박스 원점을 (0,0)으로 정규화합니다.** 경로 좌표를 부모 좌표계 기준으로 써 놓고 `node.x = 0`을 하면 그 차이만큼 어긋납니다. 실밥이 공 밖으로 튀어나간 원인이었습니다. 생성 후 **측정값으로 중앙 정렬**하세요: `n.x = (size - n.width) / 2`.
10. **`query()` 셀렉터 값에 `/`를 넣을 수 없습니다.** `query('INSTANCE[name^=Row/]')`는 `unexpected character '/'`로 실패합니다. `findAll(n => n.name.startsWith('Row/'))`를 쓰세요.
11. **페이지를 `setCurrentPageAsync` 하기 전에는 `page.children`이 비어 보일 수 있습니다.** 다른 페이지의 자식을 필터링해 지우는 코드가 조용히 아무것도 안 지웁니다. 대상 페이지로 전환한 뒤에 조작하세요.
